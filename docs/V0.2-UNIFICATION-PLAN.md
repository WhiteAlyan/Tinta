# Tinta v0.2 — Unification Plan (consolidated)

**What this document is:** the one list to actually follow for v0.2. It
reconciles three inputs that don't fully agree with each other:

1. **The original vision** — `docs/archive/TINTA-FEATURE-AUDIT-MAXIMUM-v0_3.md`
   §54–59, written before v0.1 existed. Ambitious: canonical concepts,
   shared engines (Entity/Relationship/Event/Rule/Query/Generator/
   Scenario/Revision), full UI unification (Modal/Inspector/Panel/
   Command registry/Shortcut registry).
2. **A grounded external audit** — measured the actual current codebase
   (`closeModal()` really is called from 54 sites, `openDrawerShell()`
   really is already a proper shell) and proposed a narrow, four-pass,
   low-risk plan built entirely from what it found.
3. **Two more aspirational external suggestions** (your sister's/Zai's,
   and a second "Unified Object Architecture" one) — individually
   interesting ideas (BaseRecord, Command Bus, Schema Registry, universal
   Reference layer, generic Form/Picker/Inspector framework) presented as
   a from-scratch rewrite.

**The reconciliation, in one rule:** the original vision's own §57 already
said it — *"do not refactor blindly, define what each concept means
first, then migrate implementations toward the canonical model."* v0.1
already answered "what does each concept mean" for most of these,
concretely, in working code. Where it did, that's the canonical model —
don't build a second, more abstract one on top of it. Where v0.1 left the
same concept genuinely duplicated across files with no canonical version
anywhere, that's real v0.2 work. This document sorts the archive's ideas
and both audits' suggestions into those two buckets, verified against
current source rather than assumed.

---

## Reality check: what the archive's ambitious list assumed vs. what v0.1 actually built

The archive's Phase 4 ("Shared engines") and the two aspirational docs'
"Command Bus / Schema Registry / generic Record" proposals were written
assuming a green field. v0.1 already answered several of them concretely
— re-abstracting these would be building a second system next to a
working, tested one, not unifying anything:

| Archive's proposed engine | What v0.1 actually built | Verdict |
|---|---|---|
| Entity engine | `entityType`/`chapterType` + custom fields — already record+schema, already extended to two record kinds | **Already the canonical model. Don't touch.** |
| Rule engine | Domain-agnostic rule-system foundation (magic/skill/tech/religion/etc. all share one engine already) | **Already done, exactly as envisioned.** |
| Query engine | Field-scoped `field:value` syntax, one `searchProject()`, `QUERY_FILTER_FIELDS` table | **Already done (the Query pass).** |
| Generator engine | One seeded RNG (`createRng`/`randomSeed`) threaded through every generator | **Already done.** |
| Revision engine | Manual/auto snapshots (chapters + entities, shared cap logic) + a separate undo/redo stack for live edits | **Two engines on purpose, not a gap** — a restore-and-look system and a Ctrl+Z stack solve different problems; forcing them into one would blur that distinction, not clarify it. |
| Canon/Provenance | `canonStatus` + `authoritySource`, both dispatch-by-kind across entities and rule systems | **Already done (§45).** |
| Relationship engine (as one polymorphic table) | Entity-relationships and scene-relationships, deliberately separate, separately tested | **Declined below — see "What v0.2 is NOT."** |
| Universal Inspector | `openContextDrawer()` dispatcher already exists, dispatching entity/scene/reference/ruleNode/mapMarker/timelineEvent/annotation through one shell | **Substantially already done** (Navigation/Context pillar). Extending it to new kinds as they're added is the right ongoing pattern — no rewrite needed. |

**What's left is narrower than either the archive or the aspirational
docs assumed** — which is good news, not a disappointment. It means the
actual v0.2 work is closer to Document-5-sized than
Maximum-Tinta-sized.

## The plan: ordered passes, smallest/safest first

Each pass: full smoketest suite green before starting, green again after,
`node --check` clean, a real regression test where the fix is behavioral.
Same discipline every pass this whole project has used.

### Pass 1 — Shared modal shell (`modal.js`) — ✅ COMPLETE
**Why first:** retires the exact bug class that's bitten this project
multiple times (`closeModal()` doubling as a global state-reset,
54 call sites all trusting it to behave). `openDrawerShell()` is the
proof this pattern already works here — it owns teardown, an objectURL
registry, and outside-click with the capture-paired-listener fix. Modals
get the same shell: `openModal({ title, body, onClose })`, with `onClose`
scoped **per-open** rather than one global function every caller shares.
- **Migrated onto it, smallest first:** `annotationsModal.js`,
  `wordCheckModal.js` → `grammarModal.js`, `generatorModal.js` → all 22
  inline `app.js` sites, cheapest first. Done — see `ROADMAP.md`'s "Pass 1
  complete" entry for the full per-site migration log, including the two
  fit questions raised along the way (`openCommandPalette`'s
  `palette-backdrop`, confirmed a CSS modifier and not a separate shell;
  `openImageLibrary`'s cleanup, moved from `closeModal()` into its own
  `onClose` and fixing a latent unconditional-reset bug as a side effect).
- **Verification:** `module-load.smoketest.mjs` catches import-chain
  breaks; `modal.smoketest.mjs` (40 assertions) asserts the shell's own
  contract (teardown, one `onClose` per open, no listener stacking on
  repeated opens, and — added mid-pass — re-entrant `onClose` calls that
  themselves open a new modal don't get clobbered). Full 37-file
  smoketest suite green after every single migration throughout the pass.

### Pass 2 — Finish the `dom-utils.js` safe-rendering migration — ✅ COMPLETE
**Why this is real, not cosmetic:** at the time this plan was written, only 7 of 110 `innerHTML =` sites in
`app.js` used the safe `html\`...\`` auto-escaping pattern (~6%) — most of
the smaller modal files were at 0%. This exact gap caused four separate
real injection bugs found and fixed across this project (a chapter-type
label, backup.js's warnings list, a reference's `source` field, a linked
scene's title). Finishing it retires the whole bug *class*.
- **Order:** the files with the fewest sites first (fast wins, builds
  confidence), `app.js` last (the biggest single
  chunk of remaining risk — done in the smallest slices that still pass
  the suite, not one giant sweep). Most of the migration landed across
  the sessions between this plan's writing and its completion; this
  session finished and verified it.
- **Final-slice log (this session):** audited every `innerHTML =` site in
  every module with `rg` — **zero dynamic sites anywhere in the app are
  assigned anything except `toBridge(html\`...\`)`**. The only non-`toBridge`
  assignments left in the entire codebase are teardown clearings
  (`= ''`) and one pure-static string (readAloud's "System default"
  `<option>`, nothing interpolated, nothing to escape). grammarModal.js's
  two list renders — the last hand-joined, manually-escaped dynamic sites
  (dictionary list, style-guide list) — were migrated onto `html\`\`` as
  the final slice.
- **Verification:** existing smoketests don't cover markup escaping
  directly — spot-checked the migrated sites the way the hardening pass
  did (traced every dynamic value through to its render; the two `raw()`
  call families that remain — `selected` attribute markers and the
  tag-chip bar's trusted `extraStyle` — are deliberate, documented, and
  feed from code-controlled values, with the one user-facing `raw(synopsis)`
  in Outline pre-escaped through `renderMentionsHtml` before it reaches
  `raw()`). Full suite green after every slice.

### Pass 3 — View modularization — ✅ COMPLETE
**Why:** the render functions used to live inline in `app.js`; only Corkboard and Decisions were extracted when this plan was written. "Same systems, same place" — finding "the References code" meant grepping a monolith instead of opening a file.
- **Order:** extracted independently-followable views one at a time
  (References, Systems, Map, Timeline, Snippets, Health, Stats — each is
  its own render function + its own event wiring, low coupling to the
  rest). Write/Notes/Search deliberately remain inline, exactly as this
  plan specified — they're the most entangled
  with shared module-level state (`activeChapterId` etc.) and the
  highest-traffic views, so they're where a mistake costs the most; they
  were explicitly out of this pass's scope, not forgotten.
- **Extraction log, complete:** Stats, Snippets, Timeline, and Health
  landed in earlier sessions (Health first required the four `setActive*Id`
  setter exports — see healthView.js's header). This session extracted
  the last three, each with the full suite green before starting and
  after:
  - **mapView.js** — `activeMapId`/`selectedMarkerId`/`mapImageUrl`,
    `revokeMapImageUrl()`, and the five map render functions moved
    wholesale; `setActiveMapId` moved with the state and is re-exported
    from app.js so healthView.js's import (and module-load.smoketest.mjs's
    export assertions) never changed. app.js's render() still enforces the
    "background object-URL lives only while Map is showing" rule, now by
    calling the module's exported `revokeMapImageUrl()`.
  - **referencesView.js** — `activeReferenceId` + `referenceTagFilters`
    moved; project-switch's tag-filter reset now goes through the module's
    exported `resetReferenceTagFilters()` (same contract as the old inline
    `referenceTagFilters = new Set()`, one caller);
    `tagFilterBarHtml`/`wireTagFilterBar`/`filterByTagSet` stayed in app.js
    (Notes uses them too) and are now exported for this second caller.
  - **systemsView.js** — `activeSystemId`, both render functions, and
    `openSystemNodeModal` (exists solely for this view) moved; imports the
    Pass 1 modal shell, the generator seam (starter-system modal + the
    `activeSystemIdFromGenerator` pickup), and app.js's `capitalize`.
  - The three views' jump-target setters are imported back into app.js
    (Search's jump rows write through them) and re-exported from it —
    `export { setActiveMapId, setActiveReferenceId, setActiveSystemId }` —
    the same live-binding trick as the utility re-export. Drawer.js needed
    zero edits: it already coupled to these views at the DOM level
    (`data-map-id`/`data-reference-id`/`data-open-system` row attributes).
  - Shared helpers that had been module-private in app.js gained exports
    for their new callers: `openImageLibrary`, `resolveEntityAvatar`, and
    the tag-chip trio above. Nothing else in app.js's surface changed.
  - app.js went from 7,793 lines at this session's start to ~7,060 after;
    sw.js's SHELL_FILES and module-load.smoketest.mjs's module list grew
    by the three new files (39 modules, 142 exports verified).
- **Verification:** `module-load.smoketest.mjs` after every extraction
  (38→39 modules as the new files landed);
  the Playwright nav-sweep spec (already wired up, passing) is a real
  net under selector-level regressions here specifically — this is what
  it was set up in anticipation of. Full smoketest suite green after
  every single extraction.

### Pass 4 — The recurring small-duplication cleanups — ✅ COMPLETE
Four independently small, independently safe fixes, found by this
session's own audit rather than either external document:
- **Outside-click listener helper.** The same "added a document-level
  click listener with no remove-before-add guard" bug was found and
  fixed four separate times (snippet menu, drawer, Library grid, Resume
  view). A shared `bindOutsideClick(el, handler)` (always remove-then-add
  internally) makes the whole class structurally impossible to
  reintroduce a fifth time.
- **Toast duplication.** `showGoalCelebration` and `showToast` are
  near-identical — `showToast`'s own comment admits it was "generalized
  out of" the other, which was never migrated to call it.
- **Tag/chip-filter duplication.** Library's genre/storyType/language
  filters, Notes' `entityTagFilters`, References' `referenceTagFilters` —
  three independent hand-rolled "toggle a Set, render chips, Clear
  button" implementations. (This is also *why* the closeModal-
  entanglement bug happened — these had no single obvious home.)
- **The `[[mention]]` regex**, copy-pasted in three files
  (`mentions.js`, `drawer.js`, `store.js`'s `MENTION_RE`) rather than one
  exported constant.
- **Multiple-em-dash prose strings.** Not a code-comment cleanup — the
  634 em-dashes in `store.js` alone are almost entirely internal
  comments (579/634 checked), out of scope since users never see them.
  The real, in-scope list is user-facing copy where a single string
  strings *two or more* em-dashes together as a parenthetical-aside
  tic: ~20 lines across `app.js`, `backup.js`, `drawer.js`,
  `decisionsView.js`, `generatorModal.js`, and two doc-template strings
  in `store.js` (audited this session, not yet fixed). Explicitly
  **not** touching single-em-dash strings (the large majority) or the
  paired-dash UI convention used as a placeholder/divider (`"— Unset
  —"`, `"— None (top-level) —"`, `"— or —"`) — those aren't prose
  asides, they're an intentional, already-consistent UI pattern.

**Done, see `ROADMAP.md`'s "v0.2 Pass 4" entry for the full per-item log.**
Re-auditing the "~20 lines" turned out to be closer to 6 genuine bracketing
asides once ternary branches and paragraphs with two independent
single-dash sentences (not a real aside) were correctly excluded — fixed:
`app.js`'s manuscript-export note and entity-type note, `backup.js`'s
auto-backup note, `generatorModal.js`'s starter-system note, and
`store.js`'s glossary template (both duplicate copies).

### Pass 5 — Dissolve `app.js`'s utility re-exports — ✅ COMPLETE
Mechanical, done last (lowest risk, but only meaningful once Pass 3 had
reduced how many files import from `app.js` in the first place):
`q`/`escapeHtml`/`escapeAttr` → direct `dom-utils.js` imports in every
consumer file.
- **Completion log (this session, by verification):** every former
  consumer (annotationsModal.js, backup.js, generatorModal.js,
  wordCheckModal.js, grammarModal.js, readAloud.js, sprintPanel.js) now
  imports these directly from `./dom-utils.js` — a repo-wide `rg` finds
  **zero importers of `q`/`escapeHtml`/`escapeAttr` from app.js**.
  app.js's re-export line is retained on purpose, per its own comment:
  module-load.smoketest.mjs asserts app.js provides exactly these exports
  (a regression test for the s28 bug where `html` was imported from
  app.js back when app.js only re-exported `escapeHtml`), so removing the
  line would trade a harmless, documented shim for a failing test and a
  reopened "does not provide an export named X" risk. The pass's goal —
  no module reaching *through* app.js for utilities — is met and
  enforced by the audit above; the export line itself is now a
  test-asserted compatibility surface, not a live dependency path.
- **Verification:** `module-load.smoketest.mjs` verifies every module's
  imports resolve; the audit grep above is the pass's real gate.

## What v0.2 is explicitly NOT doing (and why)

Declined, not overlooked — each of these was specifically considered
against the actual codebase and rejected for concrete reasons, so a
future session doesn't have to re-litigate them from scratch:

- **A generic Command Bus / Event Bus.** Earns its cost when multiple
  independent consumers need to react to the same mutation without
  knowing about each other. Tinta has exactly one consumer per mutation
  today (call the store function, call `render()`) — this solves a
  problem the app doesn't have, at real cost to a stable, tested
  mutation path that Real Revision (undo/redo) was just built directly
  on top of.
- **A Schema Registry / generic `Form.render({fields})` / `ObjectPicker`.**
  None of the real bugs found across this entire project trace back to
  "forms are hand-written" — they trace back to escaping, listener
  leaks, and state living in the wrong place (exactly what Passes 1–4
  above fix). Building a generic form-rendering engine is itself a
  framework project, for a problem that hasn't caused pain yet.
- **Merging entity-relationships and scene-relationships into one
  polymorphic `Relationship` table.** They have genuinely different
  validation rules today (separate, real smoke-test files —
  `relationship-history.smoketest.mjs`, `tier3.smoketest.mjs` — because
  the domain rules actually differ). Same reasoning already applied
  earlier this project to `entityType`/`chapterType`: forcing a shared
  shape usually grows a pile of `if (domain === ...)` escape hatches,
  which is worse than two honest, separate functions.
- **A `BaseRecord`/capability-mixin class hierarchy.** The `uid()`
  prefix discipline (32 distinct prefixes) already gives every record a
  consistent identity story without one. A thin `stampedId(prefix)`
  helper applied opportunistically gets the real benefit; a formal class
  hierarchy is ceremony this codebase's own culture has correctly
  avoided so far.

## Explicitly out of scope for v0.2 (separate list — real feature gaps, not refactor work)

These are still open from the archive doc's original audit, confirmed
zero code as of this pass. They're **features**, not unification —
don't let them creep into the v0.2 passes above:

- Breadcrumbs, back/forward history, tabs, split editor, multi-pane
  workspace, saved layouts, exact-text anchors, return-to-origin nav
  (§2.4 — Navigation/workspace; "smart resume" is now partially covered
  by the Resume view, the rest is still open)
- Onboarding experience levels (Simple/Normal/Maximum — confirmed your
  own original scope, §52: "workspace profiles, not product editions,"
  not settings-locked) + the welcome-back screen + quote auto-detection
  (manual quote-saving shipped this session; the other two are still
  open, deliberately, per the discussion that led to it)
- Everything in the archive's §5 onward (Character arc structure,
  Mystery toolkit, Themes/Motifs, Culture/Species/Language/Religion/
  Politics/Economy/Technology/Cosmology, Simulation levels 1–5, Impact
  analysis, AI features, Collaboration/Sync/Plugins) — all confirmed
  zero, all explicitly v0.1-scope feature work or later, not v0.2
  architecture work

## v0.3+ (not started, correctly not started yet)
Per the archive's own Phase 6 and final philosophy: performance,
accessibility, mobile, visual polish, and extensibility-proper come
*after* v0.2's unification, not layered on top of the current
duplication. Doing them first would mean polishing architecture that
hasn't earned it yet — exactly what the archive's own §56 (core rule of
v0.1) and this project's "no premature refactoring" habit both already
warn against.

## Post-v0.2.1 addendum — the registry pass (Session 27)

Re-reading the archive's §55 against source after the canvas-and-trio
pass showed three Phase 5 items that had never been audited, plus Phase 2
never having produced its written deliverable. All closed here; the
fourteen-concept verdicts live in `docs/CANONICAL-MODELS.md`.

- **Command registry + shortcut registry (`commands.js`).** Palette
  commands, the app-level keydown handler, and the Settings help table
  were three hand-synced surfaces; they're one registry now, with the
  widget-local boundary documented in the module header. The palette
  gained runnable command rows (Undo/Redo); the help table gained the
  Undo/Redo rows it had always been missing. Behavior-neutral otherwise,
  including the undo/redo text-field guard and per-entry preventDefault
  semantics.
- **Notifications.** All 27 native `confirm()` sites (9 files) migrated to
  one themed `confirmDialog()` (modal.js) with alertdialog semantics,
  focus management, supersession, and the host-modal-safe Escape capture.
  The Canvas rename's OK/Cancel became a labeled two-action choice. One
  known remnant, deliberately left: the Canvas link label still uses
  native `prompt()` (future `promptDialog()` candidate).
- **Inspector.** `openContextDrawer` dispatches 8 kinds — the §2.5 wish
  list is fully covered after `openRelationshipDrawer` closed the
  relationship gap the Navigation/Context pass had deferred.
- **Phase 2 deliverable.** `docs/CANONICAL-MODELS.md`: the architecture
  map plus all fourteen canonical concepts with definitions and verdicts.
- **Verification:** commands.smoketest.mjs (69) + modal.smoketest.mjs's
  confirmDialog sections (19 new); 44/44 modules, 184 exports; full suite
  green; live browser pass on dispatch, confirm, and peek flows.
